# D&D Dungeon Crawler (Mega Drive)

A grid-based first-person dungeon crawler for the Sega Mega Drive / Genesis, in the vein of
*Eye of the Beholder* and *Dungeon Master* (step movement, 90°-turns, no free-look), built with
[SGDK](https://github.com/Stephane-D/SGDK). This is the technical setup: toolchain, project
skeleton, and a working proof-of-concept renderer. No game content yet.

## Toolchain

Same setup as the other Mega Drive projects in this workspace:

- **SGDK 2.11** via the [doragasu/docker-sgdk](https://gitlab.com/doragasu/docker-sgdk) Docker image — no local SGDK install needed.
- **BlastEm** to run the ROM (`brew install blastem` or similar).
- `./build.sh` — builds `out/rom.bin` in the container (`./build.sh clean` to clean).
- `./run.sh` — runs the last build in BlastEm.
- `.vscode/tasks.json` — the same two as build/run tasks (Cmd+Shift+B to build).

## Rendering approach

The Mega Drive VDP has no hardware scaling or texture mapping, so — like the original EOB/DM-style
engines — the 3D view is not raycast; it's built from pre-shaded wall/floor/ceiling *tiles*
composited onto the BG_B plane as nested rectangles (near → mid → far → vanishing point), based on
a 3-cell lookahead into the map grid from the player's position and facing. Side walls/openings and
a blocking front wall are detected per depth ring and drawn with the matching depth-shaded tile.
This is cheap (a handful of `VDP_setTileMapXY` writes, only on movement, not per frame) and keeps
the view entirely on BG_B, leaving BG_A free for HUD text — same split the other projects use for
map vs. HUD.

See `src/dungeon_view.c` for the ring/depth geometry and compositing logic.

## Project structure

```
src/
  main.c              Init, input (grid movement + 90° turns), game loop, HUD text
  dungeon_map.c/.h     Map grid (wall test data), player position/facing, movement rules
  dungeon_view.c/.h    First-person renderer: BG_B tile compositing by depth ring
  game.h               Shared includes/constants
  boot/                SGDK boot files (ROM header, startup assembly)
res/
  resources.res        Asset manifest, compiled by SGDK's rescomp
  resources.h          Declares the compiled asset symbols (generated, but committed for IDE use)
  gfx/dungeon_tiles.png  Placeholder wall/floor/ceiling tileset, generated by tools/make_dungeon_tiles.py
tools/
  make_dungeon_tiles.py  Regenerates the placeholder tileset (16 tiles, indexed PNG)
```

## Current state

Boots to a static test maze (`src/dungeon_map.c`) with a first-person view and a debug HUD line
(facing + coordinates). D-Pad Up/Down walks forward/back, Left/Right turns 90°. Wall/floor/ceiling
art is procedurally generated placeholder brick texture — swap `res/gfx/dungeon_tiles.png` for real
pixel art later; the tile *slots* (see the docstring in `tools/make_dungeon_tiles.py`) are what
`dungeon_view.c` indexes, so keep that order if you replace it.
